          ██ Key concepts                                                                                               
                                                                                                                        
          Concept        │ Meaning                                                                                      
          ───────────────┼────────────────────────────────────────────                                                  
          Channel        │ Interest group bound to one object type                                                      
          Message        │ Ethereum object published to a channel                                                       
          Session        │ One active broadcast transaction                                                             
          Strategy       │ Coding-specific implementation                                                               
          Chunk          │ Header plus strategy-specific data                                                           
          Preamble       │ Session metadata to initialize strategy                                                      
          Routing update │ Strategy-specific local state advertisement                                                  
                                                                                                                        
          Sessions are keyed by (channel, message_id). Origin sessions hold the full message and seed chunks;           
          relay sessions reconstruct. Both are explicitly opened and closed so slot-scoped traffic does not             
          leak forward.

          ██ Three stream types                                                                                         
                                                                                                                        
          Protobuf over multiplexed streams. Every stream begins with a protocol selector.                              
                                                                                                                        
          Stream │ Lifetime                    │ Purpose                                                                
          ───────┼─────────────────────────────┼──────────────────────────────────                                      
          BCAST  │ per connection              │ handshake, subscribe, unsubscribe                                      
          SESS   │ per session, unidirectional │ open session, routing, completion                                      
          CHUNK  │ ephemeral, unidirectional   │ one chunk header and payload                                           
                                                                                                                        
                                                                                                                        
                                     enum Protocol {                                                                    
                                       PROTOCOL_UNSPECIFIED = 0;                                                        
                                       PROTOCOL_BCAST       = 1;                                                        
                                       PROTOCOL_SESS        = 2;                                                        
                                       PROTOCOL_CHUNK       = 3;                                                        
                                     }                                                                                  
                                                                                                                        
                                     message Selector {                                                                 
                                       Protocol protocol = 1;                                                           
                                     }                                                                                  
                                                                                                                        
                                                                                                                        
          Unknown selectors are cancelled. Non-BCAST streams before handshake are cancelled.

          ██ Control plane: BCAST                                                                                       
                                                                                                                        
          Long-lived per-peer control stream.                                                                           
                                                                                                                        
          Handshake exchanges protocol version, subscribed channels, and a peer identity placeholder.                   
                                                                                                                        
          After handshake, peers send Subscribe(channel) and Unsubscribe(channel). New subscribers are                  
          retroactively enrolled into active sessions for that channel.

          ██ Session plane: SESS                                                                                        
                                                                                                                        
          SESS opens one peer-to-peer view of a broadcast session.                                                      
                                                                                                                        
          Sess.Open carries channel, message ID, strategy preamble, and an optional initial routing update.             
          Bundling the routing update removes a round trip and reduces early redundant sends.                           
                                                                                                                        
                                                                                                                        
                       message Sess {                                                                                   
                         oneof frame {                                                                                  
                           Open session_open = 1;                                                                       
                           Update routing_update = 2;                                                                   
                         }                                                                                              
                                                                                                                        
                         // Open is the first frame on a SESS stream, establishing the session.                         
                         message Open {                                                                                 
                           string channel = 1;                                                                          
                           string message_id = 2;                                                                       
                           bytes preamble = 3;                                                                          
                           bytes initial_update = 4;                                                                    
                         }                                                                                              
                       }                                                                                                
                                                                                                                        
                                                                                                                        
          When a node reconstructs:                                                                                     
                                                                                                                        
                                                                                                                        
                                    reset inbound SESS stream with error code 0x01                                      
                                                                                                                        
                                                                                                                        
          Means "I reconstructed; further chunks unnecessary." Remote peers cancel pending sends. Disconnect            
          without this signal means the peer departed.

          ██ Data plane: CHUNK                                                                                          
                                                                                                                        
          One unidirectional stream per chunk. Header first, then exactly data_length raw bytes.                        
                                                                                                                        
                                                                                                                        
                                     message Chunk.Header {                                                             
                                       string channel = 1;                                                              
                                       string message_id = 2;                                                           
                                       bytes  chunk_id = 3;                                                             
                                       uint32 data_length = 4;                                                          
                                     }                                                                                  
                                                                                                                        
                                                                                                                        
          Leans into QUIC-like transports: independent flow control, cheap ephemeral streams, parallelization,          
          natural cancellation, HTTP/3-style header-then-body. The framework can stop reading useless streams           
          and free transport capacity quickly.

          ██ Chunk acceptance                                                                                           
                                                                                                                        
                                                                                                                        
                                     HaveChunk / DedupKey                                                               
                                       -> read header                                                                   
                                       -> VerifyChunk                                                                   
                                       -> TakeChunk                                                                     
                                       -> maybe complete                                                                
                                       -> maybe Decode                                                                  
                                                                                                                        
                                                                                                                        
          VerifyChunk can be sync or async. Chunks enter strategy state only after verification succeeds.               
                                                                                                                        
          Some inbound reads share a usefulness group (RS: duplicate shard index; RLNC: chunks for a                    
          generation after full rank). The framework ties grouped reads to a shared cancellation context. When          
          the strategy decides the group is satisfied, the framework cancels the rest.

          ██ Session lifecycle                                                                                          
                                                                                                                        
                                                                                                                        
                                    Relay:  Consuming -> Decoding -> Reconstructed                                      
                                    Origin: Origin                                                                      
                                                                                                                        
                                                                                                                        
          Relays accept verified chunks until completeness; decode runs in the background after.                        
                                                                                                                        
          When TakeChunk returns complete = true:                                                                       
                                                                                                                        
             1. framework signals reconstruction to peers                                                               
             2. framework starts background decode                                                                      
             3. strategy must reject further chunks                                                                     
                                                                                                                        
          Decode failure is non-recoverable. There is no path back to consuming.

          ██ Strategy / framework boundary                                                                              
                                                                                                                        
             •  The framework owns: peer connections, stream multiplexing, session lifecycle, and event-loop            
                plumbing.                                                                                               
             •  The strategy owns: encoding/decoding, chunk verification, routing state, dispatch policy, and           
                coding-specific identifiers.                                                                            
                                                                                                                        
          One strategy instance per session. Important methods:                                                         
                                                                                                                        
                                                                                                                        
                                     NewOrigin / NewRelay                                                               
                                     AttachPeer / DetachPeer                                                            
                                     HaveChunk, DedupKey                                                                
                                     VerifyChunk, Verified                                                              
                                     TakeChunk                                                                          
                                     RoutingUpdate                                                                      
                                     PollRouting, PollChunks                                                            
                                     ChunkSent                                                                          
                                     Progress, Decode, Close                                                            
                                                                                                                        
                                                                                                                        
          The channel run loop serializes most calls. After every state-mutating event:                                 
                                                                                                                        
                                                                                                                        
                                     drainPolls = PollRouting then PollChunks

          ██ Reed-Solomon strategy                                                                                      
                                                                                                                        
          Systematic erasure coding: k data shards + n-k parity shards; any k of n reconstruct.                         
                                                                                                                        
          Strengths: independently verifiable chunks, no novel cryptography, familiar in Ethereum through               
          PeerDAS-style coding.                                                                                         
                                                                                                                        
          Limitation: relays cannot recode; they forward exact shards. Novelty depends on spreading distinct            
          shards. As a node accumulates shards, the next random shard is less likely to be useful: the coupon           
          collector tail. RS mitigates with bitmap routing and shard allocation policy.

          ██ RS encoding and verification                                                                               
                                                                                                                        
          Origin: choose k, parity, chunk length; split padded message into data shards; compute parity; hash           
          every shard; hash original message; insert into emit planner.                                                 
                                                                                                                        
                                                                                                                        
                                     message Preamble {                                                                 
                                       int32 num_data   = 1;                                                            
                                       int32 num_parity = 2;                                                            
                                       int32 length     = 3;                                                            
                                       repeated bytes hashes = 4;                                                       
                                       bytes hash = 5;                                                                  
                                     }                                                                                  
                                                                                                                        
                                                                                                                        
          Per chunk:                                                                                                    
                                                                                                                        
                                                                                                                        
                                   hash(shard data) == preamble.hashes[shard_index]                                     
                                                                                                                        
                                                                                                                        
          After decode:                                                                                                 
                                                                                                                        
                                                                                                                        
                                     hash(decoded message) == preamble.hash                                             
                                                                                                                        
                                                                                                                        
          Bad shards are rejected before entering strategy state. Unauthenticated RLNC has no equivalent.               
                                                                                                                        
          SHA-256 is provisional. Future modes: builder signatures, Merkle commitment over shard hashes.

          ██ RS routing and dispatch                                                                                    
                                                                                                                        
          Routing state is a shard bitmap; bit i = peer has shard i. Incoming bitmaps are OR-merged. Emission           
          is threshold-gated: default waits for 50% present; 0 always emits; DisableBitmap turns it off.                
                                                                                                                        
          Dispatch is driven by an emit planner: least allocated shard first, ties broken by per-relay                  
          Fibonacci hashing. The strategy skips shards the peer already has, are in flight to that peer, or             
          exceed relay redundancy budget.                                                                               
                                                                                                                        
          Origins are unconstrained. Relays are budget-constrained.

          Term               │ Meaning                                                                                  
          ───────────────────┼──────────────────────────────────────────                                                
          Generation         │ independent partition of the message                                                     
          Basis              │ independent chunks for a generation                                                      
          Coefficient vector │ linear combination metadata                                                              
          Rank               │ number of independent chunks held

          groups so each scalar is canonical), produce standard-basis chunks, asynchronously produce extra

          ██ RLNC routing and dispatch                                                                                  
                                                                                                                        
          Routing state is a HaveList:                                                                                  
                                                                                                                        
                                                                                                                        
                                     (generation, rank)                                                                 
                                                                                                                        
                                                                                                                        
          It reveals progress, not exact chunk identity. When a peer reaches full rank for a generation, sends          
          to that peer for that generation are cancelled and new sends skip it.                                         
                                                                                                                        
          Origins use pending basis chunks plus async redundancy, with on-demand recoding fallback. Relays              
          always recode.                                                                                                
                                                                                                                        
          For each peer, the strategy selects an eligible generation and emits a fresh random combination.              
          Generation selection prefers the lowest dispatch count for that peer.

          ██ RLNC budgets and bounds                                                                                    
                                                                                                                        
          Each accepted inbound chunk grants ForwardMultiplier units of relay budget for that generation. Each          
          relay dispatch consumes one unit. Failed sends restore budget. Decoded relays bypass the budget so            
          they can serve pull recovery.                                                                                 
                                                                                                                        
          For each (peer, generation), track chunks sent, in flight, and received from that peer. Stop sending          
          when:                                                                                                         
                                                                                                                        
                                                                                                                        
                                     interaction count >= current generation rank                                       
                                                                                                                        
                                                                                                                        
          This avoids sending a peer combinations of information it already contributed.

          ██ Security and open questions                                                                                
                                                                                                                        
          Framework-level authentication is delegated to strategies (RS chunks can be precommitted; RLNC                
          chunks are generated dynamically; future schemes may need async crypto). The framework still needs            
          DoS hardening around stream exhaustion, chunks for unopened sessions, routing poisoning, and false            
          inventory.                                                                                                    
                                                                                                                        
          Open:                                                                                                         
                                                                                                                        
             •  Ethereum-specific identity types for peers, channels, and messages                                      
             •  channel discovery, access control, duty-derived membership                                              
             •  application-driven vs strategy-driven session disposal                                                  
             •  transport abstraction beyond QUIC-like streams                                                          
             •  framework-visible authentication envelope                                                               
             •  routing update validation and DoS mitigation design

          ██ Takeaways                                                                                                  
                                                                                                                        
          Erasure-coded broadcast changes propagation from serial full-message forwarding to parallel                   
          useful-chunk dissemination.                                                                                   
                                                                                                                        
          The framework gives strategies control over coding, routing, verification, and dispatch while                 
          keeping stream and session mechanics shared.                                                                  
                                                                                                                        
          RS is the practical deployment path today. RLNC remains the benchmark for what recoding can do, but           
          its authentication and IP constraints keep it out of the production path.
